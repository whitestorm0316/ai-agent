大厂 / 平台型：招「架构级」

做的是基础设施层（Agent 平台、Harness、工具链）。要求大厂背景 + 出海英语能力，职级高、薪资天花板高，但坑位少。

SaaS / 硬件 / AI 原生：招「全栈 + 懂场景」

零散需求最多，单家公司平均 2 个岗位。要既懂传统业务（ERP、嵌入式、机器人），又能把大模型接进去。这类岗位对「非大厂背景」最友好。

4技术栈全景：从模型到运维的五层

把 JD 里零散的技术名词按层次归位，能看清一件事——Agent 工程师不是「更懂模型的人」，而是「更会做系统的人」。

1

基础设施与模型层（大脑）

GPT-4o / Claude / Gemini，国产 Qwen、DeepSeek、GLM、Kimi。核心不是背模型参数，而是模型无关化开发——能按成本、延迟、中文效果灵活切换，不被单一厂商锁定。

2

协议与工具层（手脚）

Function Calling / Tool Use 是硬门槛；MCP（Model Context Protocol）正在成为工具接入的事实标准，A2A 解决 Agent 之间的任务委托。要求能把企业内部的 CRM / ERP / SQL / 审批系统封装成标准工具。

3

编排与逻辑层（神经系统）

ReAct（简单任务）、Plan-and-Execute（强流程）、LangGraph（状态机 / 条件分支 / 循环重试，工业级首选）、CrewAI（角色驱动多 Agent）、AutoGen（对话驱动）。低代码平台 Dify / Coze 用于快速验证。

4

检索与记忆层（知识库）

RAG 全链路：切分策略、Embedding、混合检索、重排序。向量库 Milvus / Chroma / Qdrant / Pinecone。记忆分三层——短期（对话上下文）、长期（向量库历史知识）、工作记忆（当前任务状态）。2026 的趋势是 RAG 从「万能架构」回归为「特定场景组件」。

5

工程与运维层（骨架）

Python + AsyncIO 异步编程、FastAPI 服务化、Docker / K8s、Redis / Kafka、可观测性工具 LangSmith / Langfuse。这一层是「Demo 能不能上线」的分水岭。

5招聘方到底在考什么：七个能力簇

把 JD 的职责与要求去重归纳，得到七个能力簇。按「JD 提及密度 + 面试追问深度」排序。

工程落地能力 P0 核心

几乎每份 JD 都写的一句话：「能将 Demo 工程化到生产级」。拆开是——异常处理、限流、降级、重试、监控、可观测性、高并发。

  • 工具调用超时 / 脏数据 / 重复执行怎么办
  • 线上 CPU 飙高、内存持续上涨怎么排查
  • 这是面试官最爱深挖、也最容易暴露短板的地方

Agent 架构设计 P0 核心

能说清为什么用这个架构，而不是只会调框架。

  • ReAct / Plan-and-Execute / Supervisor 的适用边界
  • 为什么用多 Agent？改单 Agent 会怎样？
  • 子 Agent 如何分工、分发、合并全局状态
  • 结论冲突如何仲裁，何时需要人工介入

RAG 全链路 P0 核心

不是「会搭一个知识库问答」，而是要能解释每个参数的依据。

  • Chunk 大小、重叠窗口怎么定
  • 用 Recall@K、MRR 做过实验调优吗
  • 混合检索、重排序、长上下文 vs RAG 的取舍

工具调用与协议 P1 重要

Agent 区别于聊天机器人的本质能力。

  • Function Calling / Tool Use 成功率如何定义与提升
  • 超时、返回脏数据、重复执行的兜底策略
  • MCP 工具链封装（占比 10%，但增长最快）

记忆系统 P1 重要

「记得住、忘得掉、查得到」是工程难点。

  • 短期 / 长期 / 工作记忆分别怎么设计
  • 历史对话什么场景做摘要、什么场景做召回
  • mem0 / A-Mem / pgvector 等方案选型

评估与成本控制 P1 重要

模型有随机性，没有评估就没有迭代。

  • LLM-as-Judge、Reflection 自反思机制
  • 任务完成率、工具调用准确率、幻觉率、Token 消耗
  • 效果 / 效率 / 成本一体化指标

业务抽象能力 分水岭

把「帮我看看这家公司有没有风险」拆成：查工商库 → 抓舆情 → 比对监管处罚 → 检查财务异常 → 生成摘要。识别哪些环节该自动化、哪些必须人工介入、如何在模型不确定性 / 执行效率 / 业务容错率之间找平衡——这一条是高级工程师和普通开发者的分界线，也是 JD 里写不出来但面试一定会问的东西。

7面试实际会追问什么

从大厂 AI Agent 岗位的真实面经看，面试不会考概念背诵，而是沿着你的项目一路深挖到系统底层。

一面：项目深挖 + RAG + 工程基础

  • 完整讲一遍项目的流程与你负责的模块
  • RAG 离线建库 / 在线检索分别做了什么
  • Chunk 大小与重叠窗口的确定依据
  • ASR 识别效果怎么评估，专有名词怎么处理
  • 隐私数据的传输 / 存储 / 访问安全
  • Agent 工具调用成功率怎么定义与提升
  • 进程 / 线程 / 协程的区别与适用场景
  • 手写：LRU Cache（get / put O(1)）

二面：架构 + 模型原理 + 系统能力

  • Agent 相比传统工作流优势在哪、生产难题是什么
  • Token 划分原理、为什么以 Token 为处理单元
  • Transformer / Self-Attention，Q、K、V 的作用
  • Lost in the Middle；上下文窗口是不是越大越好
  • 超长对话怎么处理：滑动窗口 / 摘要 / 向量召回
  • SFT 流程，PPO / DPO / GRPO 的差异
  • 为什么用多 Agent，多 Agent 结论冲突如何仲裁
  • 线上 CPU 飙高 / 内存泄漏的排查思路
  • mmap、writev 解决什么问题
  • 手写：扁平 JSON 还原树 / 二叉树锯齿层序遍历
一句话总结面经：面试官会持续追问方案选型理由、边界异常处理、线上故障排查。没有真正动手落地过的项目，一定会在深挖环节暴露。「Demo 玩具」和「生产级」的区别，就是能不能答上异常处理、容错降级、效果评估这三类问题。

深圳的三个特色方向

端侧 / 硬件 Agent

大疆、vivo、安克、极米、拓竹。要求懂端侧 AI、嵌入式、硬件联调，纯软件思维做不了。这是深圳独有的溢价区。

金融 Agent

微众银行已有 80+ 数字员工，平安、招商、中信都在推。要求合规意识 + 金融知识 + AI 技术三重背景，可审计、可解释、可回滚是前提。

大厂平台层

腾讯 ima、字节飞书 Aily / 火山引擎、金蝶 Agent Harness。做的是基础设施和工具链，要求架构能力 + 大厂背景 + 出海英语。

行动建议：① 先把 Python + LangGraph + RAG + Function Calling 跑通，做出一个能讲 30 分钟的项目；② 刻意补工程细节——异常处理、降级、限流、评测，这是面试的分差所在；③ 选一个深圳本地场景（客服 / 供应链 / 硬件交互 / 金融风控）做垂直深耕，比泛泛地学框架更有议价权；④ 投递优先级：AI 原生公司 / SaaS（门槛友好、项目主导）→ 硬件公司（深圳特色）→ 大厂（要求高但天花板高）。
