10 周转行路线：从后端开发到深圳 AI Agent 岗位

你的起点比大多数人好得多——面试里最难补的「工程落地能力」你已经有了。所以这条路线的重点不是学编程，而是补上 AI 应用层的语义、做两个能讲 30 分钟的项目、把已有的工程能力翻译成 Agent 场景的语言。

你的起点
有后端 / 全栈开发经验
你的目标
尽快拿深圳 Agent 岗 offer
可投入时间
10–20 小时 / 周 · 共 10 周

1先做减法：你能跳过什么

深圳 Agent 岗位 JD 里，有相当一部分是「传统软件工程基本功」。这部分你已经有底子，不要重复学，那是纯浪费。把省下的时间全投到下面「必须补」的清单上。

可以跳过 / 只复习

编程语言基础（Python 语法、面向对象）跳过
进程 / 线程 / 协程、并发与并行只复习
HTTP / REST / WebSocket、API 设计跳过
数据库、SQL、Redis 基础用法跳过
Linux、Git、Docker 基础跳过
微服务、消息队列、K8s 运维跳过
模型训练 / 微调 / 论文复现暂缓

最后一条说明：JD 里「模型微调」只占约 35%，且要求 PyTorch + 训练经验，是算法岗的地盘。你用后端背景去拼这块不占优，用工程能力去拼才占优。等拿到 offer 再补不迟。

必须补（按优先级）

LLM 应用语义层：Prompt 结构、Token、上下文窗口、模型差异P0

记忆系统：短期 / 长期 / 工作记忆P1
评估体系：LLM-as-Judge、黄金数据集、量化指标P1
可观测性：Tracing、Token 成本、延迟归因P1
你的核心策略：别人在面试里答不上「工具调用超时怎么办」「线上内存泄漏怎么排查」「如何限流降级」——这些对你来说是日常。你要做的不是学新东西，而是把已有经验换一套 Agent 的术语讲出来，再补上 AI 应用层的语义。这是最高效的转行路径。

310 周逐周计划

勾选左侧方框可以记录进度（会自动保存在本地）。

第 1 周 LLM 应用语义层 + 手写 Function Calling 约 15h
学什么Prompt 结构（System / Few-shot / CoT）、Token 与上下文窗口、主流模型差异（GPT-4o 通用稳、Claude 长文本推理强、DeepSeek / Qwen / GLM 中文性价比高）。重点：不用任何框架，用原生 API 手写一遍工具调用循环。
动手做一个命令行小助手：能根据用户问题自主决定调用「查天气 / 算数 / 读本地文件」三个工具，并把结果组织成回答。全程手写 JSON Schema 和调用循环。
为什么手写一遍，你才会真正理解「框架到底替你做了什么」。面试问「Function Calling 的原理」「工具调用失败怎么处理」，你能从底层答。
验收标准：能画出一次完整的工具调用时序图（模型返回 tool_calls → 你执行 → 回填结果 → 模型生成最终答案），并说清 token 是怎么消耗的。
第 2–3 周 RAG 全链路 + 建评估体系 约 30h
学什么文档切分策略（固定长度 / 递归 / 语义）、Embedding 模型选型、向量库（先用 Qdrant 或 Chroma）、相似度检索、混合检索（BM25 + 向量）、重排序（BGE-reranker）、长上下文 vs RAG 的取舍边界。
动手做企业知识库问答系统。关键不是跑通，而是做实验：Chunk 大小取 256 / 512 / 1024，重叠取 0 / 50 / 100，跑 20 条测试问题，记录 Recall@K 和 MRR，做出对比表格。
为什么面试官必问「Chunk 大小怎么定的」——答「官方默认值」就出局，答「我做过三组对比实验，512 + 重叠 50 在 Recall@5 上最优」就赢了。这张实验表格是你第一个能拿出手的面试素材。
验收标准：手里有一张 Chunk 参数对比实验表（含 Recall@K / MRR 数据），并能解释为什么重排序能提升效果。
第 4–5 周 Agent 编排：LangChain 入门 → LangGraph 落地 约 30h
学什么LangChain 核心概念（Chain / Agent / Memory / Tool）快速过一遍，然后主力投入 LangGraph：图状态机、状态持久化（checkpointer）、条件分支、循环重试、Human-in-the-Loop（interrupt_before）。理解 ReAct 与 Plan-and-Execute 的适用边界。
动手做把第 2–3 周的 RAG 升级成 Agent：能自主决定「查知识库 / 调外部 API / 做计算 / 反问用户」。用 LangGraph 画出状态图，加一条失败重试路径。
加餐把其中一个工具封装成 MCP Server（约 4 小时工作量）。JD 里 MCP 只占 10%，但 2026 年它是工具调用的事实标准，成本低、面试谈资高。
验收标准：能讲清「为什么这个场景用 LangGraph 而不是普通 Chain」「为什么用多 Agent / 不用会怎样」「工具调用超时和返回脏数据怎么兜底」。
第 6–7 周 生产化 + 评估 + 记忆系统（你的主场） 约 30h
学什么FastAPI 服务化与异步、限流、降级、重试、熔断；可观测性（LangSmith 或 Langfuse：Tracing、Token 成本、延迟归因）；评估（黄金数据集 + LLM-as-Judge，指标：任务完成率、无效工具调用率、幻觉率、Token 消耗）；记忆三层（短期 / 长期 / 工作记忆）。
动手做把第 4–5 周的 Agent 做成生产级服务：加并发处理、加限流降级、加完整 Tracing、加自动化评测 Pipeline（能一键跑出准确率和成本报告）。
为什么这一周是你相对别人最大的优势区。后端经验让你做这些又快又稳，而大多数转行者在这里是空白。把这一块做成可讲的「生产故事」，面试分差就拉开了。
验收标准：有一份自动化评测报告（准确率 / 成本 / 延迟），能演示「限流触发后的降级行为」，能说清一次线上故障的排查路径。
第 8–9 周 项目二 + 作品集包装 约 30h
做什么选一个深圳本地场景做垂直项目，形成与项目一的对比：
· 单 Agent + 强工程 + 明确业务（如 AI 客服、供应链查询）
· 多 Agent + 复杂编排（如「需求分析 → 检索 → 生成 → 自审」协作链）
包装GitHub 仓库 + 清晰 README + 架构图 + 量化结果（响应时间、准确率、成本下降幅度）。有技术博客加分——JD 里明确列为加分项。
注意两个项目要能形成对比叙事：一个证明「我懂业务落地」，一个证明「我能设计复杂架构」。只有一个项目的话，面试官会怀疑是抄的。
验收标准：不看代码，能在 30 分钟内把两个项目的架构、选型理由、踩过的坑、优化前后数据讲完。
第 10 周 面试冲刺 + 批量投递 约 15h
手写算法LRU Cache（O(1)）、TopK 小根堆、扁平 JSON 还原树、二叉树锯齿层序遍历。大厂一面/二面高频。
八股Token 划分原理、Self-Attention 与 QKV、Lost in the Middle、上下文窗口是否越大越好、超长对话处理方案、SFT / PPO / DPO / GRPO 差异、mmap / writev。
投递BOSS 直聘（直聊，主战场）+ 猎聘（中高端）+ 牛客（校招）。深圳优先南山、福田、龙岗坂田。先用 2–3 家非目标公司练手，再投心仪的。
验收标准：能白板手写 LRU Cache 和小根堆；项目答辩能扛住连续 5 层追问不卡壳。

42026 年技术栈选型（别学错东西）

今年的生态有两个重要变化，直接决定你该学什么——AutoGen 已被弃用，LangChain 退居原型定位。

层次该学什么市场现状 / 理由
编排层 LangChain（原型）→ LangGraph（生产） LangChain 占编排层 70.6% 份额、134k stars，但独立基准显示复杂工作流下 Token 与延迟高于 LangGraph。策略是「LangChain 做发现层，生产迁 LangGraph」。
工具协议 MCP 工具调用事实标准，GitHub 相关仓库 1700+，81.1% 应用用官方 SDK。2026 年 7 月最大更新是无状态化（取消 Session），Server 可像普通 HTTP 服务水平扩展。
协作协议 A2A（了解即可） Google 发起，已移交 Linux Foundation 治理，150+ 组织生产部署。解决 Agent 之间互相委派任务，与 MCP 正交。求职阶段不必深挖，知道定位就行。
前端交互 AG-UI（了解即可） 基于 SSE + JSON-RPC，解决流式输出、工具执行可视化、Agent 主动提问。做 C 端 Agent 产品时会用到。
多 Agent 框架 CrewAI，或 Microsoft Agent Framework 重要变化 AutoGen 已进入维护模式，2025 年 10 月与 Semantic Kernel 合并为 MAF，2026 年 4 月发布 1.0 GA。新项目直接上 MAF，别再从 AutoGen 学起。
低代码 Dify / Coze（会用即可） 快速验证原型用，JD 里占 35%。但别把它当核心竞争力——面试考的是你能不能手写。
向量库 Qdrant 或 Chroma 起步 先学一个吃透原理，Milvus / Pinecone 用法大同小异，面试问的是切分与检索策略而非 API。
可观测性 LangSmith / Langfuse，OpenTelemetry 三层：日志、指标（延迟 / 吞吐 / 错误率 / Token）、链路追踪。没有 Tracing 数据，优化就是盲猜。
评估 黄金数据集 + LLM-as-Judge 指标：答案准确率、轮次、无效工具调用率、噪声工具使用率。评估标准要自己掌握，这是壁垒。
安全治理是个现成的加分点：数据显示只有 37.2% 的 MCP 应用在工具执行前设置了人工审批关卡。你在项目里加一个工具审批 / 权限拦截层（高风险工具 require_approval），既是真实工程能力，又能在面试里讲出「AI Agent 的安全边界」——大多数候选人根本想不到这一层。

5两个项目怎么设计

项目不在多，在于能形成对比叙事。下面两个方向，一个证明落地、一个证明架构。

项目一：单 Agent + 强工程 + 明确业务

选一个深圳本地场景——AI 客服、供应链查询、硬件设备问答、金融合规问答都可以。

  • RAG 知识库 + 工具调用（查订单 / 查库存 / 调内部 API）
  • LangGraph 编排，含失败重试与人工介入节点
  • FastAPI 服务化 + 限流 + 降级 + 完整 Tracing
  • 自动化评测 Pipeline，输出准确率 / 成本 / 延迟报告

证明的是：我懂把 Agent 做成生产系统。

项目二：多 Agent + 复杂编排

设计一条协作链，例如「需求分析 Agent → 检索 Agent → 生成 Agent → 自审 Agent」，或 Supervisor 模式下的分工调度。

  • Agent 之间的分工、任务分发、全局状态合并
  • 输出冲突时的仲裁机制（谁说了算 / 何时转人工）
  • 防死循环：最大轮次、状态去重、终止条件
  • 每个子 Agent 的能力用 MCP 工具封装

证明的是：我能设计复杂架构，而不只是调框架。

关于「玩具项目」的界定：面试官区分玩具和生产级，看的是三件事——有没有异常处理、有没有容错降级、有没有效果评估。你的两个项目必须同时具备这三样，否则和教程里抄的没区别。

6面试考点清单

来自大厂 AI Agent 岗位真实面经。带 ⚑ 的是你作为后端可以直接拿分的题。

一面：项目深挖 + RAG + 工程基础

  • 完整讲一遍项目流程与你负责的模块
  • RAG 离线建库 / 在线检索分别做了什么
  • Chunk 大小与重叠窗口的确定依据
  • 用 Recall@K、MRR 做过调优实验吗
  • Agent 工具调用成功率如何定义与提升
  • 工具超时 / 脏数据 / 重复执行怎么兜底 ⚑
  • 进程、线程、协程的区别与适用场景 ⚑
  • 并发与并行的区别 ⚑
  • 隐私数据的传输 / 存储 / 访问安全 ⚑
  • 手写：LRU Cache（O(1)）

二面：架构 + 模型原理 + 系统能力

  • Agent 对比传统工作流的优势与生产难题
  • Token 划分原理、为什么以 Token 为单元
  • Transformer / Self-Attention，Q、K、V 的作用
  • Lost in the Middle；上下文窗口越大越好吗
  • 超长对话：滑动窗口 / 摘要 / 向量召回怎么选
  • SFT 流程，PPO / DPO / GRPO 的差异
  • 为什么用多 Agent，冲突如何仲裁
  • 线上 CPU 飙高 / 内存持续上涨怎么排查 ⚑
  • mmap 是什么、解决什么问题 ⚑
  • writev 如何聚合缓冲区减少系统调用 ⚑
  • 手写：扁平 JSON 还原树 / 二叉树锯齿层序遍历
⚑ 标记的题就是你的护城河。转行者通常在这些题上失分，而你有真实经验。面试时主动把话题往「生产环境的异常处理」上引，让面试官在你的优势区提问。
